Heavy Transport & Modification Garage

vehicle bay diagnostic tickets — click one to pop the hood

Ticket #FH4-014 ▾
Forza Horizon 4
Fault: system-wide freeze, every 5–10s, only during a drive
Diagnosis

A faulty ASUS VBIOS update was dropping CPU and GPU power to ~20W in short bursts — not a game bug, a power-delivery bug wearing one.

Fix

Clean Windows reinstall with that VBIOS update skipped entirely. Kept a backup VBIOS (GA107.rom) on hand in case a rollback's ever needed.

Tools

Fresh Windows install, VBIOS backup/flash

Ticket #FH4-021 ▾
Forza Horizon 4
Fault: "Unable to connect to Live configuration servers"
Diagnosis

Stale, corrupted Xbox Live auth tokens sitting in Windows Credential Manager — the network path was fine, the handshake wasn't.

Fix

Closed FH4, Steam, Xbox App and Microsoft Store, then cleared every Xbox-related credential so it re-authenticated clean.

Tools

Windows Credential Manager

Ticket #FH6-006 ▾
Forza Horizon 6
Fault: instant crash the moment "Drive" is selected
Diagnosis

The active Proton build couldn't keep up with this title's descriptor-heap handling under VKD3D.

Fix

Switched to proton-cachyos-11.0-20260520-slr-x86_64 and added launch options: PROTON_VKD3D_HEAP=1 VKD3D_CONFIG=enable_experimental_features,descriptor_heap %command%

Tools

Steam compatibility settings

Ticket #AC-011 ▾
Assetto Corsa
Fault: won't launch, or launches into graphical corruption
Diagnosis

Vulkan-to-DX11 translation choking under Proton on this particular setup.

Fix

Switched to GE-Proton; when it still crashed, added PROTON_USE_WINED3D=1 %command% to the launch options.

Tools

Steam compatibility settings, trial launches

Ticket #ACC-004 ▾
Assetto Corsa Competizione
Fault: same launch instability, different remedy needed
Diagnosis

Vulkan/DX11 translation again — this time it's the sync model tripping things up.

Fix

GE-Proton plus PROTON_NO_ESYNC=1 PROTON_NO_FSYNC=1 %command% to stabilize the sync model.

Tools

Steam compatibility settings

Ticket #WD-002 ▾
Watch Dogs
Fault: doesn't open at all when Play is clicked
Diagnosis

Ubisoft Connect never got installed inside the Proton prefix in the first place.

Fix

Forced it through with the Proton Hotfix runtime.

Tools

Steam compatibility settings

The Control Console

system scripts & automation — click a line to run it back

admin@workshop — PowerShell
PS C:\> .\DG_Readiness_Tool_v3.6.ps1 ▾

IssueVMware couldn't get hold of VT-x — Windows had it locked up running Device Guard and Virtualization-Based Security in the background, and VT-x only serves one master at a time.

FixRan the DG Readiness script elevated, confirmed disabling Device Guard/VBS, restarted — VT-x freed up for VMware.

PS C:\> net stop wuauserv; net stop bits; net stop cryptsvc; net stop trustedinstaller ▾

IssueUpdate KB5065426 kept failing mid-install because the services it depends on weren't in a clean state.

FixStopped wuauserv, bits, cryptsvc and trustedinstaller; renamed the SoftwareDistribution and catroot2 folders so Windows would rebuild them fresh; restarted the same services. Update installed clean after.

PS C:\> reg add "HKLM\System\CurrentControlSet\Control\TimeZoneInformation" /v RealTimeIsUniversal /d 1 /t REG_DWORD /f ▾

IssueEvery swap between Windows and Bazzite threw the system clock off — the Linux side wrote the hardware clock in UTC, Windows expected local time, and each boot re-fought the other for it.

FixTold Windows to treat the hardware clock as UTC too, ending the tug-of-war (the Bazzite side got a matching flag via timedatectl).
